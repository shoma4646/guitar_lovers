# guitar_lovers プロダクト定義（2026-08）

作成: プロダクト方針転換の意思決定ドキュメント

前提: 旧構成（tuner / practice / history / news の4タブ全部入り）は、チューナー・メトロノーム・練習記録・学習コンテンツのいずれの軸でも既存プレイヤーと正面衝突し、個人開発として勝ち目が薄いと判断した。既に動いている「YouTube WebView再生 + ABループ + メトロノーム + 練習記録」の組み合わせに絞り、他社と重ならない定義へ再設計する。

---

## 1. 一行定義

**YouTubeでギターを練習する人のための、練習メニュー化アプリ。**

YouTubeの動画そのものを見せるアプリではなく、動画内の「このフレーズを練習しよう」という区間を、翌日以降も反復できる練習メニューへ変換するレイヤーとして位置づける。

## 2. コアループ

```
動画で区間を見つける
  → フレーズとして保存（区間・BPM・目標BPM）
  → 今日の練習メニューからワンタップで再開
  → BPMを少しずつ上げながら反復
  → 結果を記録 → 次回の目標BPMが更新される
  → 目標BPMに到達したら「卒業」として積み上がる
  → 翌日の練習時刻にリマインド通知が「今日の1本」を名指しで呼び戻す
```

「動画を探す」「弾く」の間にあった手作業（区間を覚えておく、毎回シークし直す、前回のBPMを思い出す）を消すことが価値の中心。ループの末尾（卒業・リマインド）は継続利用のための仕組みで、詳細は「9. 継続利用の仕組みと定義」に置く。

## 3. ターゲット

独学でYouTubeを見ながら練習を組み立てている中級者。

- 教則コンテンツ・レッスンにお金を払う層ではなく、無料動画で自分なりの練習メニューを組み立てている層
- 「このフレーズ、目標のテンポまで持っていきたい」という反復練習の習慣がすでにある、または持ちたいと思っている人
- 初心者向けの体系的カリキュラムは求めていない（それは Yousician / Fender Play の役割）

## 4. できること（MVP）

- YouTube動画のURL/IDを読み込み、区間（A点/B点）を指定してABループ再生
- 区間を「フレーズ」として名前・BPM・目標BPMとともに保存
- 今日の練習メニューに保存済みフレーズが並び、タップで区間再生・メトロノームBPMまで自動復元
- 練習結果（○/△/×）を記録すると、次回の目標BPMが自動で更新される
- フレーズ別のBPM推移をProgressタブで確認できる
- 今日の練習メニューの先頭に「今日の1本」が理由付きで強調され、回数付きの目標（既定3回）から結果記録まで一直線に進める
- 目標BPMに到達したフレーズは「卒業」としてProgressタブの卒業一覧に積まれる
- 主指標は「今週の練習日数」。連続日数は補助表示に留める
- ローカル通知のリマインドが、練習時刻の傾向に合わせて「今日の1本」のフレーズ名と目標BPMを届ける

## 5. やらないことリスト

明示的に対象外とする。将来的にニーズが強く裏付けられた場合のみ再検討する。

| 項目 | 理由 |
|---|---|
| 曲ライブラリ・タブ譜 | コンテンツホルダーになると運用負荷が跳ね上がる。Ultimate Guitar / Songsterr の領域 |
| レッスン・カリキュラム | 教育コンテンツの制作・監修が必要になり、個人開発の規模を超える。Yousician / Fender Play の領域 |
| 音源分離・コード検出 | 技術的難度が高く、差別化の中心でもない。Moises の領域 |
| ニュース配信 | 差別化に寄与しない静的コンテンツ。旧構成から削除済み |
| コミュニティ・SNS共有 | ネットワーク効果がないと機能しない。個人開発の初期スコープ外 |

## 6. 競合との線引き

| プレイヤー | 領域 | guitar_lovers との違い |
|---|---|---|
| GuitarTuna | チューナー＋タブ譜＋レッスン | コンテンツを自前で持つ「学習コンテンツ提供者」。guitar_loversはコンテンツを持たない |
| Yousician / Fender Play | 体系的カリキュラム学習 | 初心者向けの構造化学習が中心。guitar_loversは「自分で見つけた動画」が前提 |
| Moises | 音源分離・コード検出 | 音声処理技術が核。guitar_loversは既存YouTube動画のメタ情報（区間・BPM）を扱うだけ |
| Soundbrenner | メトロノーム単体 | 単機能ツール。guitar_loversはメトロノームを「フレーズ練習」に従属させる |
| Guitar Practice Journal | 練習タイマー・記録・YouTubeループ | 最も構成が近い直接競合。guitar_loversは「フレーズ単位のBPMプログレッション（前回→今日の目標）」を主軸に据える点で差別化する |

**差別化の核**: コンテンツを持たず、「他人の動画を自分の練習メニューへ変換する」レイヤーに徹すること。運用コストがかからず、YouTubeの動画資産（無限に増え続ける）にそのまま乗れる。

> 注: 上記の競合情報は二次情報（ChatGPTを介したリサーチ）に基づく。ストア掲載文やマーケティング資料を作成する段階では、各社の実際の機能・規模を一次ソースで再確認すること。

## 7. 将来のマネタイズ仮説（未実装）

現時点では仮説として置くのみで、実装しない。

- フレーズ保存数のフリーミアム上限（無料は少数、有料で無制限）
- 進捗グラフの参照期間制限（無料は直近◯日、有料で全期間）
- ペア機能や複雑な分析は現段階では想定しない（Steadyのような関係性アプリとは異なり、guitar_loversは個人利用が前提）

課金導入は、フレーズ×BPMプログレッションのコアループがユーザーに定着したと確認できてから検討する。

## 8. 情報構造（タブ構成）

- **Practice**（起動直後の主役）: 今日の練習メニュー + 動画ロード・ABループ・メトロノーム・フレーズ保存
- **Progress**: フレーズ別BPM推移 + 卒業一覧 + 週次統計（主指標は今週の練習日数）
- **Tuner**: マイクによるリアルタイムピッチ検出でチューニングを行う（実用ユーティリティとして残す。主役ではない）
- **Settings**（モーダル）: プライバシー・サポート導線 + 練習リマインドのON/OFFと送信時刻

## 9. 継続利用の仕組みと定義

実装が依存する定義と数値。変更するときはここを先に直す。

### 定義

- **到達BPM**: フレーズに保存された到達BPMと、「弾けた（○）」記録の最大BPMの大きい方
- **卒業**: 到達BPMが目標BPM以上。卒業日は目標BPM以上で初めて弾けた記録の日で、後から前進しない。目標BPMを引き上げて未到達になれば卒業は解除される
- **練習した日**: 練習セッションまたは練習結果の記録がある日。練習時間はセッションのみから集計する
- **今日の1本**: 今日の練習メニューの先頭。並び順は「前回あやしい/弾けなかった → 記録が古い順 → 未記録 → 卒業済み」。卒業済みは今日の1本に選ばない
- **リマインドの対象フレーズ**: 今日の1本と同じ選定。全て卒業済みなら最後に作成したフレーズ
- **リマインドの送信日**: その日にフレーズ保存・練習結果・練習セッションのいずれかがあれば翌日。無ければ当日の送信時刻（過ぎていれば翌日）

### 数値

| 項目 | 値 |
|---|---|
| 目標BPMの刻み | 5（到達BPM以上で弾けた記録が最新なら、次の練習から+5。同日でも進める） |
| 回数目標の既定 | 3回 |
| BPMの許容範囲 | 40〜240 |
| リマインドの傾向算出 | 直近28日の練習記録。同じ曜日に2件以上あればその曜日、無ければ全曜日の中央値。2件未満なら20:00 |
| リマインドの前倒し | 中央値の30分前、15分単位に切り捨て |
| リマインドの時刻範囲 | 07:00〜22:00（自動算出・手動指定とも） |
| 手動時刻の刻み | 30分 |
| 通知文面のフレーズ名 | 20文字で切る |

### 方針

- 連続日数を主指標にしない。途切れた瞬間に離脱要因になるため、主指標は今週の練習日数
- ポイント・バッジ・ランキング・損失回避で縛る仕掛けは採用しない
- リマインドの予約は1件だけを固定IDで持ち、起動・前面復帰・データ変更のたびに作り直す。アプリを開かない限り翌日以降の予約は作られない（複数日の先行予約は未実装）
